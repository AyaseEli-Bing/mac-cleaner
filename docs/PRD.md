## 1. 原始需求复述

> 开发一个用于清理 macOS 系统数据的工具，能扫描并清理系统缓存、日志文件、临时文件、回收站残留及其他可安全删除的系统数据以释放磁盘空间。支持预览各类可清理项及其占用大小，提供选择性清理与一键全清功能。包含安全保护机制以避免误删关键系统文件，清理前显示确认提示，并记录清理历史与释放的空间总量。

**需求拆解关键词**：扫描（多类目）→ 预览（体积可视化）→ 选择（多选 / 全选）→ 安全校验（黑名单 + 白名单 + 二次确认）→ 执行（可中断）→ 记录（历史 + 累计释放量）。

## 2. 产品目标

| # | 目标 | 量化验收指标 |
| --- | --- | --- |
| G1 | **安全零事故**：任何一次清理操作都不得导致系统不可用或用户数据丢失 | 1) 覆盖全部硬编码黑名单路径的自动化用例 100% 通过；2) 对黑名单路径执行"强制删除"请求时，系统必须拒绝并在日志中留痕；3) 全量回归测试中系统关键路径（`/System`、`/usr`、`~/Documents`、`~/Library/Mail`、`~/Library/Keychains` 等）文件数量前后差值 = 0 |
| G2 | **扫描结果可信、看得懂**：让用户清楚知道每一份空间被谁占用了 | 1) 扫描覆盖 ≥ 10 个可清理类目；2) 任一类目体积统计与 `du -sk` 结果偏差 ≤ 5%；3) 非开发者用户能在 30 秒内找到"占用最大的一个类目" |
| G3 | **清理过程可控、可中断**：用户始终掌握主动权，随时可刹车 | 1) 默认进入 dry-run 预览态，未经二次确认不得触发真实删除；2) 扫描与清理均可在 3 秒内响应取消指令；3) 清理进度实时可见（已处理项 / 总项数 + 已释放字节数） |
| G4 | **效果可度量**：用户能直观感知"这个工具有没有用" | 1) 展示单次清理释放量与历史累计释放总量；2) 历史记录持久化保存 ≥ 100 条，重启应用/重启电脑后不丢失；3) 历史每条记录可下钻查看清理了哪些具体路径 |
| G5 | **一条命令启动**：普通用户零配置即可使用 | 1) 在项目根目录执行单条启动命令后，自动完成构建产物检查 → 启动服务 → 打开浏览器，全程 ≤ 15 秒；2) 无需手动安装任何 Python 第三方包；3) 无需 sudo 也能完成默认类目的扫描与清理 |

## 3. 用户故事

| # | 用户故事 | 覆盖需求点 |
| --- | --- | --- |
| US-1 | 作为**普通 Mac 用户**，我希望打开工具后能立刻看到"磁盘总容量 / 已用 / 可用"和"预计可回收空间"，以便快速判断我的磁盘是不是真的需要清理 | 仪表盘、磁盘概览 |
| US-2 | 作为**普通 Mac 用户**，我希望扫描结果按类目分组展示（缓存、日志、临时文件…），每个类目显示体积与占总可回收量的百分比，以便我一眼看出空间被谁吃掉了 | 类目分组、体积统计与占比 |
| US-3 | 作为**谨慎型用户**，我希望先预览每一项的具体路径和大小，再决定清不清，以便我心里有底、不会误删重要文件 | dry-run 预览、路径明细 |
| US-4 | 作为**普通 Mac 用户**，我希望可以只勾选我放心的几个类目做部分清理，而不是被迫全部清理，以便保留我还需要的东西 | 选择性清理（多选） |
| US-5 | 作为**追求效率的用户**，我希望有"一键全清"按钮，一次点完就把所有安全项清掉，以便省去逐项勾选的麻烦 | 一键全清 |
| US-6 | 作为**普通 Mac 用户**，我希望在真正删除前弹出一个明确的确认窗口，告诉我"即将清理 X 项 / 释放 Y GB"，需要我再点一次确认，以便我不至于手滑就删了东西 | 删除前二次确认 |
| US-7 | 作为**担心误删的用户**，我希望工具自带危险路径保护，即使我全选也不会碰系统文件，以便我可以放心使用一键全清 | 危险路径黑名单、SIP 规避 |
| US-8 | 作为**开发者用户**，我希望可以选择性开启 Xcode DerivedData、模拟器、npm/Homebrew 缓存等高级类目，以便清理掉几 GB 甚至几十 GB 的开发垃圾 | 开发者高级类目（默认关闭） |
| US-9 | 作为**普通 Mac 用户**，我希望在清理进行到一半时发现不对可以立刻中止，并且已经删掉的部分不会让工具卡死或崩溃，以便我随时能反悔 | 可中断、错误处理 |
| US-10 | 作为**普通 Mac 用户**，我希望每次清理后能在"历史记录"里看到这次清了什么、释放了多少，以及累计一共释放了多少，以便我知道这个工具的价值 | 清理历史、累计释放总量 |
| US-11 | 作为**权限受限的用户**，我希望当某目录无权访问时，工具明确告诉我"无权限，已跳过"，而不是报错中断或卡住，以便扫描总能跑完 | 权限降级处理 |
| US-12 | 作为**普通 Mac 用户**，我希望界面默认跟随系统深色主题、文字说明用大白话而不是技术黑话，以便我不需要懂技术也能安全使用 | 深色主题、文案通俗化 |

## 4. 需求池

> 优先级定义：**P0 = 必须有（不做则产品不成立）**；**P1 = 应该有（显著影响体验与安全完整性）**；**P2 = 可以有（锦上添花）**

### 4.1 扫描能力（SCAN）

| 编号 | 需求描述 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| SCAN-01 | 定义**类目扫描清单**（白名单制），仅扫描清单内路径，清单外路径一律不碰 | P0 | 代码内维护一份结构化类目表，含：类目 ID、显示名称、扫描根路径列表、风险等级、默认开关状态。类目表可被前端读取并渲染 |
| SCAN-02 | 支持类目：**用户缓存** `~/Library/Caches/**` | P0 | 本机实测该目录存在且约 1.4 GB，扫描结果体积与 `du -sk` 偏差 ≤ 5% |
| SCAN-03 | 支持类目：**系统级缓存** `/Library/Caches/**` | P0 | 无权限时降级标记 `permission_denied`，不中断整体扫描 |
| SCAN-04 | 支持类目：**应用缓存** `~/Library/Containers/**/Data/Library/Caches`、`~/Library/Group Containers/**/Library/Caches`、`~/Library/Application Support/**/Cache(s)` | P0 | 仅匹配路径中包含 `Cache`/`Caches` 片段的目录，其余 `Application Support` 内容不纳入 |
| SCAN-05 | 支持类目：**用户日志** `~/Library/Logs/**`（含 `DiagnosticReports`） | P0 | 只统计与清理日志文件，不删除日志目录本身（保留目录结构） |
| SCAN-06 | 支持类目：**系统日志** `/Library/Logs/**`、`/private/var/log/**` | P1 | 默认关闭，需用户在设置中显式开启；无权限时降级 |
| SCAN-07 | 支持类目：**临时文件** `/private/var/folders/**/T/**`、`/private/var/folders/**/C/**`、`/tmp/**` | P0 | 跳过**正在被进程占用**的文件（尝试独占打开失败或删除返回 EBUSY 时记为 skipped，不得重试强删） |
| SCAN-08 | 支持类目：**回收站残留** `~/.Trash/**` | P0 | 支持"清空回收站"动议；体积统计包含废纸篓内所有条目 |
| SCAN-09 | 支持类目：**下载目录大文件** `~/Downloads/**` | P1 | 默认仅标记"单文件 ≥ 100 MB 且最后访问时间 ≥ 30 天前"的条目；阈值可在设置中调整；**默认不勾选**，需用户手动确认 |
| SCAN-10 | 支持类目：**Xcode 开发垃圾**（`~/Library/Developer/Xcode/DerivedData`、`Archives`、`iOS DeviceSupport`、`~/Library/Developer/CoreSimulator/**`） | P1 | 标记为"开发者项"，默认关闭；开启后需二次确认提示"清理后下次编译会变慢/需重新下载设备支持" |
| SCAN-11 | 支持类目：**包管理器缓存**（`~/.npm/_cacache`、`~/.cache/yarn`、`~/Library/pnpm-store`、`~/Library/Caches/Homebrew`、`~/.cargo/registry/cache`、`~/.gradle/caches`、`~/.m2/repository`） | P1 | 标记为"开发者项"，默认关闭；路径不存在时该类目显示"未安装/无此缓存"，不报错 |
| SCAN-12 | 支持类目：**浏览器缓存**（`~/Library/Caches/com.apple.Safari/**`、`~/Library/Caches/Google/Chrome/**`、`~/Library/Caches/Firefox/**`、`~/Library/Caches/com.microsoft.edgemac.**`、`~/Library/WebKit/**`） | P2 | 标记为"隐私敏感项"，默认关闭；确认弹窗中额外提示"清理后网站可能需要重新登录" |
| SCAN-13 | 支持类目：**iOS 设备备份** `~/Library/Application Support/MobileSync/Backup/**` | P2 | 风险等级=高，默认关闭；需用户输入确认文本后才可勾选（见 SEC-07） |
| SCAN-14 | 扫描结果包含每项的：完整路径、显示名称、体积（字节）、文件/目录类型、最后修改时间、所属类目、风险等级 | P0 | 前端列表可展示上述全部字段 |
| SCAN-15 | 扫描采用**后台并发执行**并输出实时进度 | P0 | 顶部进度条 + "已扫描 X 个目录 / Y GB"；并发扫描线程数可配置（默认 4） |
| SCAN-16 | 扫描可**随时中断**，中断后保留已完成部分的结果 | P0 | 点击"停止扫描"后 ≤ 3 秒内停止；已扫描结果仍可正常展示与清理 |
| SCAN-17 | 扫描结果**缓存**，避免每次切换页面重复扫描 | P2 | 结果在内存中保留；提供"重新扫描"按钮强制刷新 |

### 4.2 体积统计与可视化（STAT）

| 编号 | 需求描述 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| STAT-01 | 首页展示磁盘总览：总容量、已用、可用、可回收总量 | P0 | 数据源为 `os.statvfs`，数值与"关于本机 → 存储"误差 ≤ 2% |
| STAT-02 | 每个类目展示：体积、占"可回收总量"的百分比、条目数 | P0 | 全部类目百分比之和 = 100%（四舍五入误差 ≤ 1%） |
| STAT-03 | 类目按体积降序排列，最大项视觉突出 | P0 | 列表首项为体积最大类目，配占比进度条 |
| STAT-04 | 提供**类目占比可视化**（横向条形图或环形图） | P1 | 图例可点击，点击后跳转到对应类目明细 |
| STAT-05 | 体积单位自动换算（B / KB / MB / GB / TB） | P0 | 保留 1 位小数；< 1 MB 时显示 KB |
| STAT-06 | 计算并显示"目录树体积"时正确处理**符号链接**，不跟随软链（避免循环与重复计数） | P0 | 遇到符号链接时按链接本身大小计，不递归进入 |

### 4.3 清理执行（CLEAN）

| 编号 | 需求描述 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| CLEAN-01 | **默认 dry-run 预览**：任何清理动作前先展示"将清理 N 项 / M 个路径 / 释放 X GB"的预览清单 | P0 | 预览接口不产生任何文件系统写操作；可通过对比操作前后文件数验证 |
| CLEAN-02 | **选择性清理**：支持按类目勾选 / 取消勾选，支持类目内逐条勾选 | P0 | 勾选状态实时汇总为"已选 N 项 · 预计释放 X GB" |
| CLEAN-03 | **一键全清**：一键选中全部**已开启且通过安全校验**的类目 | P0 | 默认关闭项与风险等级=高的项不自动纳入；一键全清后仍需走二次确认 |
| CLEAN-04 | 清理执行采用**后台任务**，实时反馈进度 | P0 | 展示"正在清理 (i/N)：<路径>" + 已释放字节数实时累加 + 进度条 |
| CLEAN-05 | 清理**可中断**：中止后已完成部分保留，剩余项不再执行 | P0 | 点击"停止"后 ≤ 3 秒停止；已释放空间计入历史记录，标记状态为"已中止" |
| CLEAN-06 | 清理结果**逐项回执**：成功 / 跳过（含原因）/ 失败（含原因） | P0 | 清理完成后展示结果汇总弹层：成功 N 项、跳过 M 项、失败 K 项，失败项可展开查看原因 |
| CLEAN-07 | 支持**"移到废纸篓"替代直接删除**（可配置，默认开启） | P1 | 开启时被清理项移入 `~/.Trash` 并保留可恢复性；关闭时执行真实删除。配置项持久化 |
| CLEAN-08 | 清理完成后**自动刷新**磁盘总览与累计释放量 | P0 | 无需手动刷新，数字即时更新 |
| CLEAN-09 | 清理**目录内容但保留目录本身**（针对日志/缓存根目录） | P1 | 清理后 `~/Library/Logs`、`~/Library/Caches` 目录仍存在且可写 |

### 4.4 安全保护机制（SEC）— **一等公民需求**

| 编号 | 需求描述 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| SEC-01 | **危险路径硬编码黑名单**：内置不可删除路径清单，任何删除请求命中即拒绝 | P0 | 黑名单至少覆盖：`/`、`/System/**`、`/usr/**`（`/usr/local/**` 除外）、`/bin`、`/sbin`、`/etc`、`/var/db`、`/private/var/db`、`/private/var/root`、`/Library/Apple/**`、`/Library/Preferences`、`/Library/Keychains`、`~/Library/Keychains`、`~/Library/Preferences`、`~/Library/Mail`、`~/Library/Messages`、`~/Library/Application Support/AddressBook`、`~/Library/Application Support/MobileSync`（除非显式走 SCAN-13）、`~/Documents`、`~/Desktop`、`~/Pictures`、`~/Movies`、`~/Music`、`~/Public`、`~/Library/Mobile Documents/**` |
| SEC-02 | **SIP 系统完整性保护路径规避**：对受 SIP 保护的路径只读扫描、一律拒绝删除，并在 UI 明示"受系统保护，已跳过" | P0 | 对 `/System/Library/**`、`/usr/lib/**`、`/Library/Apple/**` 发起删除请求时，返回拒绝并在结果中标记 `protected_by_sip` |
| SEC-03 | **路径规范化校验**：删除前对路径做 `realpath` 规范化，防止 `..` 穿越与符号链接逃逸到黑名单目录 | P0 | 构造 `~/Library/Caches/../../Documents/test` 等穿越路径的测试用例，必须被拦截（100% 拦截） |
| SEC-04 | **白名单制**：只有命中 SCAN 类目清单的路径才允许进入清理队列 | P0 | 随机选取 20 个不在类目清单内的路径发起删除，全部被拒绝 |
| SEC-05 | **正在被占用的文件跳过**：删除时若文件被进程占用（OSError EBUSY / 独占锁失败），标记为"跳过-被占用"，不重试强删 | P0 | 打开一个大文件保持句柄，执行清理 → 该项状态为 skipped 且 UI 显示原因 |
| SEC-06 | **用户主目录外路径需额外确认**：涉及 `~/` 之外（如 `/Library`、`/private/var`）的清理项，在确认弹窗中单独分区展示并加醒目警示，需用户单独勾选"我确认清理系统级目录" | P0 | 未勾选该复选框时，"开始清理"按钮禁用 |
| SEC-07 | **高危类目输入式确认**：风险等级=高的类目（如 iOS 备份、下载目录大文件）需用户手动输入确认文本（如 `确认删除`）后才可勾选 | P1 | 输入不匹配时无法勾选 |
| SEC-08 | **删除前二次确认弹窗**：展示"即将清理 N 项 / 释放 X GB / 涉及路径示例 Top5 / 是否可恢复"，需点击确认按钮 | P0 | 弹窗必须包含上述 4 类信息；只有点击"确认清理"才执行 |
| SEC-09 | **单次清理上限保护**：单次清理总量超过阈值（默认 20 GB）或条目数超过阈值（默认 50,000 条）时，阻断并提示"建议分批清理" | P1 | 阈值可在设置中调整；超限时给出分批建议而非直接拒绝全部 |
| SEC-10 | **清理操作日志留痕**：每一次被拒绝、被跳过的删除尝试均写入操作日志 | P1 | 日志包含：时间戳、路径、原因码（`blacklist` / `sip` / `outside_home` / `in_use` / `permission_denied` / `not_in_whitelist`） |
| SEC-11 | **空路径/根路径熔断**：任何删除请求若解析后为空字符串、`/`、`~`、`$HOME` 本身，立即熔断拒绝 | P0 | 单元测试覆盖，必须拒绝 |
| SEC-12 | **清理前自动安全快照预览**：确认弹窗中提供"导出本次清理清单为 CSV"按钮，供用户留存 | P2 | 导出的 CSV 含路径、大小、类目、操作时间 |

### 4.5 历史记录与度量（HIST）

| 编号 | 需求描述 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| HIST-01 | 每次清理生成一条历史记录：时间、清理类目、条目数、成功/跳过/失败数、实际释放字节数、执行耗时、结果状态（完成/已中止） | P0 | 记录字段完整，可在历史页查看 |
| HIST-02 | 历史记录**持久化**存储（SQLite，Python 标准库 `sqlite3`） | P0 | 重启应用与重启系统后数据仍在；存储文件位于项目数据目录，不散落在系统目录 |
| HIST-03 | 展示**累计释放空间总量**（历史全部记录求和） | P0 | 首页显著位置展示；数值 = 所有已完成记录释放量之和 |
| HIST-04 | 历史记录可**下钻查看明细**：点击某条记录展开查看本次清理的具体路径列表 | P1 | 明细至少保留最近 5 次清理的路径级明细 |

### 5.6 页面四：设置面板（抽屉）

| # | 开放问题 | 选项 A（PM 建议） | 选项 B | 影响 |

## 8. 关键风险与应对

| 风险 | 等级 | 应对措施 |
| --- | --- | --- |
| 误删用户数据导致不可恢复 | 🔴 高 | 白名单 + 黑名单 + 路径规范化三重校验；默认移到废纸篓；二次确认；高危项输入式确认（SEC-01~SEC-12） |
| 扫描极慢（百万级小文件） | 🟡 中 | 并发扫描；符号链接不递归；扫描超时保护；进度实时可见可中断 |
| 权限不足导致系统级类目不可用 | 🟡 中 | 降级跳过 + 授权引导文案，不中断整体流程（ERR-01/ERR-03） |
| 用户对"可清理空间"预期过高，清理后感知不明显 | 🟡 中 | 首页明确区分"已用 / 可用 / 可清理"三态；废纸篓模式明确提示需清空废纸篓才真正释放 |
| 删除正在被使用的缓存导致 App 异常 | 🟡 中 | 占用文件跳过；提示用户"建议先退出相关 App" |

## 9. 交付给架构师的约束摘要

1. **安全是硬约束**：所有删除路径必须经 `路径规范化 → 白名单校验 → 黑名单拦截 → SIP 判定 → 占用检测` 五道关卡，任一不通过即拒绝并留痕。
2. **零第三方依赖**：后端仅用 Python 3 标准库；持久化用 `sqlite3`。
3. **一条命令启动**：`mac-cleaner/` 根目录下单条命令完成构建检查 + 启动 + 开浏览器；前后端同端口同源。
4. **前后端契约**：后端提供 REST JSON API（能力清单见 SYS-06），前端 Vite + React + MUI + Tailwind。
5. **默认深色主题**，风险等级用统一色彩语义（绿/黄/红）。
6. **本机实测参考**（2026-09-19 于目标机器验证）：`~/Library/Caches` ≈ 1.4 GB 存在；`~/Library/Developer/Xcode/DerivedData`、`~/Library/Developer/CoreSimulator`、`~/.npm`、`~/Library/Caches/Homebrew`、`~/.cargo` 存在；`~/.cache/yarn`、`~/Library/pnpm-store`、`~/.docker`、`~/Library/Caches/Firefox`、`~/Library/Caches/Google` 不存在（类目清单须做存在性降级处理，见 ERR-02）。
